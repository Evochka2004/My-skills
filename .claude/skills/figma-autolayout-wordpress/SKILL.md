# Автолейаути та назви шарів для WordPress

Перед змінами у файлі завантаж скіл `figma-use` (Figma MCP) і створи сесію файлу. Нічого не змінюй без потреби: дизайн має виглядати так само, як і до чистки.

## Структура
Page → Section → Container → Block → Element. Кожен рівень — окремий фрейм з Auto Layout.
- Section: на всю ширину, вертикальний Auto Layout, власні вертикальні padding.
- Container: фіксована max-width десктопа, горизонтальні padding, вирівняний по центру.
- Block: картка/колонка/група; Element: текст, кнопка, іконка, зображення.

## Auto Layout
- Жодних груп (Group) і вільно розставлених шарів усередині секцій: тільки фрейми з Auto Layout.
- Відступи тільки з сітки 4/8 px. Gap і padding задавай значеннями, а не позиціюванням.
- Resizing: контейнери — Fill / Hug, а не Fixed, де це можливо. Зображення — Fill із збереженням пропорцій.
- Вирівнювання (alignment) задавай явно, щоб у Dev Mode читалися flex-властивості.
- Сітки з колонок — горизонтальний Auto Layout із Wrap, а не копіюванням блоків вручну.

## Назви шарів
Формат `тип/назва` англійською, у нижньому регістрі з дефісами:
`section/hero`, `container`, `block/card`, `heading`, `text`, `button/primary`, `image/hero`, `icon/arrow`.
- Повторювані блоки — компоненти (Component) з варіантами, а не копії.
- Жодних «Frame 12», «Group 7», «Rectangle 3».
- Приховані й порожні шари видаляй лише після підтвердження користувача.

## Порядок роботи
1. Прочитай структуру файлу (get_metadata / скріншот) і склади план змін.
2. Покажи користувачу план і дочекайся підтвердження.
3. Працюй по секціях, після кожної порівняй скріншот «до/після»: різниці у вигляді бути не має.
4. Наприкінці дай список змін і перелік місць, де автолейаут налаштувати не вдалося.
